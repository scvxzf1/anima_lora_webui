# Krea-2 RTX 3080 速度研究：阶段 5

## 为什么要推翻 4 步短测

阶段 3 的 resident compile 三个稳态步均值 11.744s，相对历史 12.14s 看似
快 3.3%。该收益小，必须用长窗口排除加速频率和温度过渡态。

## compiled 20 步

RTX 3080、1024²、NF4、swap20、full checkpoint、resident-only compile：

- 首步（含编译）：`25.167s`
- 第 2-4 步：`12.062 / 12.046 / 12.134s`
- 第 10-12 步：`12.324 / 12.410 / 12.394s`
- 第 18-20 步：`12.570 / 12.574 / 12.647s`
- loss：`0.011963→0.002274`，梯度非零，无 NaN/Inf

步时在 20 步内单调漂移约 5%。因此 11.74s 是冷/短窗口数字，不是持续训练
速度。热稳态后 compile 约 12.5-12.65s/it。

## eager 同配置对照

当前桌面/服务常驻约 436MiB 时，eager swap20 在首个 backward OOM：还需 144MiB，
已分配 6.94GiB，reserved 未用 576.5MiB。历史相同探针曾能完成 10 步，说明
swap20 eager 是边界工作点，会随 allocator/桌面状态在 PASS/OOM 间波动。

compiled 路径报告训练期 peak `6.153GB`，且连续 20 步通过。所以 compile 在
3080 上的可靠价值是**激活计划与显存余量**，不是已证明的长训加速。

## 120 秒 BF16 GEMM 热消融

不加载模型，持续执行 Krea-2 代表性 `4608×6144 @ 6144×6144` BF16 Linear：

| 阶段 | GEMM | 温度/时钟 |
| --- | ---: | --- |
| 早段 | 6.87-7.00ms | 升温中 |
| 末段 | 7.3-7.5ms | 最高 84°C，末尾约 1800MHz |

GPU 平均功耗约 `304.7W`，接近 320W 上限，utilization 100%。纯 eager GEMM 也出现
7-9% 长时间退化，证明训练漂移不是 compile 重编译或图退化，而是 3080 热稳态。

## 修正后的判定

1. 3080 约 12s/it 主因仍是硬件大矩阵吞吐，且长训叠加约 5-9% 热降频。
2. resident compile 保留为 opt-in，因为它让当前环境从 eager OOM 变为 20 步稳定通过。
3. 不再宣称 3080 持续快 3.3%；该数字只是短窗口。长训性能优化的下一主战场是
   散热/风扇/机箱风道和可能的降压频率曲线，不是 H2D 或 padding。
4. 任何功耗/风扇/降压实验都属于主机状态修改，后续执行前需明确同意，并在
   实验后恢复原值。
