# INT8 单字节编码的误差上限（CMP 50HX 第 4/5 轮）

状态：实验 / 第 4~5 轮（P2 编码测量）
适用版本：`codex/block-swap-int8`（第 3 轮 `a11b429b` 之后）
入口命令：`.venv/bin/python -m bench.block_swap_int8.encode_error`
相关代码：`library/runtime/int8_encode.py`、`bench/block_swap_int8/encode_error.py`、`tests/test_int8_clip_encode.py`

本文件回答第 3 轮留下的问题：int8 master 的 1 Byte/元素已经能把 PCIe 流量减半，
但要作为默认项，就得把 MOSS 上 ~1.09% 的 loss 偏移压下去。原始方向给的是 3A（离群裁剪）
与 3B（NF8 查表）。本轮把两者都量到"上限"，结论是**3A 无效、3B 有效但依赖权重分布**。

## 方法

`bench/block_swap_int8/encode_error.py` 用**相对 L2 误差**（sum((r-w)²)/sum(w²)）比较四种编码，
全部保持 1 Byte/元素 + 每行 1 个 FP32 scale（字节数完全相同）：

| 编码 | 说明 |
| --- | --- |
| `base` | 现役 `quantize_weight_per_channel`，`scale = amax/127` 均匀对称 |
| `clip` | 本轮新增的 per-row 裁剪搜索（0.85~1.00 amax + 99.95 分位，取行内 L2 最优） |
| `wide` | 裁剪的理论上限：per-row 在 0.30~1.00 amax 上以 0.01 步长穷举 |
| `nf8` | 固定 NF8 码本（N(0,1) 等概率 256 级分位），每行按 amax 缩放 |
| `lloyd` | per-row 最优 256 级量化器（1D Lloyd-Max/k-means），非固定码本的收益上界 |

样本：4 组合成分布 + 真实 Anima DiT 的 `mlp.layer1.weight`（用 `safe_open` 按 key 抽样，不加载全模型）。

## 结果 1：3A（均匀量化 + 离群裁剪/scale 搜索）已否定

| 样本 | base 相对误差 | clip 收益 | wide 收益（上限） |
| --- | --- | --- | --- |
| 合成 1×14σ 离群 / 512 宽 | 6.992e-05 | +0.38% | +1.22% |
| 合成 25×5σ 重尾 / 512 宽 | 5.590e-05 | +0.48% | +1.33% |
| 合成纯高斯 / 512 宽 | 5.652e-05 | +0.57% | +1.27% |
| 合成 3×8σ / 64 宽 | 3.716e-05 | +1.90% | +0.10% |
| **真实 Anima block 0** | 3.723e-04 | +0.51% | +1.41% |
| **真实 Anima block 17** | 9.677e-05 | +0.75% | +1.92% |
| **真实 Anima block 25** | 8.864e-05 | +0.81% | +2.01% |

即使把 scale 选择完全放开（`wide`，包含会饱和 70% 元素的激进档），收益也只有 **≤2.01%**。
原因很直接：per-row 对称 int8 的相对误差已经贴着均匀量化的噪声地板
（step = amax/127，误差 ≈ step²/12，即 ≈5.2e-5 相对量级），离群值只影响它自己那一行，
而裁剪会把离群值变成饱和误差，多数行并不划算（行内 L2 搜索自动只挑划算的行）。

**结论：原始 P2 里"均方量化误差下降 60%~80%"的说法在 per-row 缩放下不成立。**

## 结果 2：3B（NF8 固定码本）有效，但依赖权重分布

| 样本 | base | nf8 收益 | lloyd 收益（拟合上限） |
| --- | --- | --- | --- |
| 合成 1×14σ 离群 | 6.992e-05 | **−69.95%** | +55.45% |
| 合成 25×5σ 重尾 | 5.590e-05 | **−103.40%** | +49.67% |
| 合成纯高斯 | 5.652e-05 | **−93.44%** | +50.27% |
| 合成 3×8σ / 64 宽 | 3.716e-05 | **−477.41%** | +90.84% |
| **真实 Anima block 0** | 3.723e-04 | **+64.34%** | +45.43% |
| **真实 Anima block 17** | 9.677e-05 | **+15.32%** | +28.04% |
| **真实 Anima block 25** | 8.864e-05 | **+13.68%** | +30.23% |

- **真实 DiT 行确实"均值附近密集、尾部稀疏"**：固定 NF8 码本把相对误差再降 **13.7%~64.3%**，
  等效约 +0.6~+4.5 dB，字节数分毫不增。原始方向三的核心判断在这一侧被证实。
- **但它不是通用替换**：对更接近高斯的行，固定高斯码本反而差 70%~477%，因为码本在中段
  （|z|≈1~2）分辨率不足，而 amax 缩放又把行摊到码本的整个跨度上。
- `lloyd`（per-row 拟合码本）上界 28%~91%，说明"拟合分布"确实还有空间，但拟合码本需要额外
  字节（除非按 block 共享一份几百字节的码本，那是另一个方案）。

## 结论与下一步

1. **3A 关闭**，`int8_encode.py` 的裁剪搜索只作为测量基准保留，不接入运行时。
2. **3B 保留但必须选择性启用**：按行（或按张量）在 uniform 与 NF8 之间择优选一，
   并用父级的 1 bit/1 字节层级标记解码方式；无条件全局切 NF8 会让高斯型权重退化。
3. **1.09% loss 偏移还没有被归因**：3A 的误差差异只有 ≤2%，而 loss 偏移是 ~1%，
   两者量级不匹配——说明偏移更可能来自别处（反量化路径的 bf16 乘法精度、多层累积、
   或探针本身的训练动力学），而不是 scale 被离群值撑大。**在归因之前不应把 int8 设为默认**。
   现有 `scripts/experiments/int8_blockswap_equivalence_probe.py` 是下一步的直接工具。

## 边界与未证明项

- 只测了**相对 L2 误差**，没有端到端 loss 对比；MSE 变化不等于 loss 偏移变化。
- 真实权重只来自**本机 Anima DiT 的 3 个 layer1 张量**；MOSS 权重不在本机，原始 1.09% 的说法
  在本轮无法复核。
- `lloyd` 用 12 轮 1D k-means 近似，且在 block 0 上给出比 NF8 更差的收益（+45% vs +64%），
  说明该实现是**下界**而非真最优；"拟合码本还有多少空间"仍未定量。
- NF8 只测了"每行按 amax 缩放"这一种缩放方式，未试按方差缩放或混合缩放。
