# Dragon 前端性能与模块边界优化（2026-08-26）

状态：历史性能基线；实现已落地
适用版本：2026-08-26 的五路由工作树，不代表当前全部 Dragon 页面

## 范围

本轮只覆盖训练配置、数据集蓝图、实时训练、历史列表和历史详情。约束是保持现有 DOM、接口语义和视觉样式不变，优先处理首屏无关资源、后台请求、连续输入重渲染和模块责任混合。后续新增的 tagging/Captioning 工作台不属于本报告的资源、浏览器或内存采样范围。

## 实现

- `page-loaders.js` 集中页面注册，所有页面通过动态 `import()` 按路由加载；加载失败会清除缓存的 loader promise，允许刷新路由重试。
- `route-styles.js` 在页面控制器执行前加载对应 CSS，并在全部候选样式完成后才替换旧路由样式；失败时清理候选 link、保留旧样式，由现有路由错误态接管，避免 FOUC 和半套样式。
- `dragon-style.css` 只保留 token、基础布局、导航和共享控件。原先误放在配置页和仪表盘样式中的 `.dragon-input`、`.dragon-btn`、`.dragon-icon` 等通用规则已原样搬到 `02a-dragon-controls.css`，页面专属 CSS 不再承担全局控件依赖。
- 导航只需要五项训练配置分类，但过去会因此加载约 19.8KB 的完整 `form-layout.js`。分类现抽到 `form-category-defs.js`，`form-layout.js` 继续兼容导出；四个非配置路由各减少 18,417B 首屏 JS，训练配置仍加载完整布局且行为不变。
- `index.js` 回到壳层编排，不再静态依赖十二个页面控制器。
- 统一 Dragon import cache token；同一物理 JS 的多 token 实例从 6 组降到 0，并增加模块图扫描门禁。
- `visibility-poller.js` 为首页与实时训练提供无重叠的递归轮询；标签隐藏时停止定时请求，返回前台立即补一轮并恢复调度。
- 数据集预设搜索使用 100ms 合并窗口，离开页面时清理待执行计时器，减少连续输入期间的整列表 DOM 重建。
- 历史筛选使用同样的输入合并与卸载清理；下拉框和统计按钮仍立即更新。
- 训练配置搜索预计算字段、章节和分组 DOM 索引，并把连续输入合并为 100ms 更新；标签切换、脏状态与初始渲染仍立即同步。
- 训练配置首屏只加载 239 项、18.8KB 的帮助摘要索引；约 119KB 的四个完整帮助分片在首次打开参数说明时才加载，并用一致性测试防止摘要漂移。
- 数据集预设库及其字段渲染依赖在用户打开“更换预设/预览”时才加载；首屏数据卡片继续由步数估算响应提供名称、数据集数、图片数和重复数，避免额外预设 API 请求。
- 模型快速选择器拆为 3.7KB shell 与 8.8KB 控制器；首屏保留原按钮和对话框 DOM，排序、模型状态与 API 控制器在首次打开时加载，并保留失败提示与重试入口。
- 历史列表的数据模型、展示层和详情控制器已拆分；`page-loaders.js` 在导入控制器前按 `taskId` 分流，列表不再加载图表、日志和样张模块，详情也不再加载集合工作台。
- `history-view.js` 仅保留详情展示，从约 42.8KB / 600 余行收缩为 24.5KB / 344 行；列表筛选与显示名称逻辑分别归入 `history-list-view.js`、`history-model.js`。
- 历史详情的详情、样张和权重请求提前并发；续训能力在详情响应后判断，并与其他请求继续重叠。首段日志改为仅在直达或切换到“日志”页签时请求，27KB 日志虚拟化模块也在该时刻动态加载。

## 第二轮运行时优化

- 训练配置把 dirty-state 计算和稳定 DOM 绑定抽到 `config-dirty-state.js`。145 个字段在挂载时索引一次；单字段输入只比较当前键、更新当前字段，保存、批量恢复和初次挂载才做全量校准。只有开启“查看修改”时，单字段变化才重新运行字段筛选。
- 实时训练把稳定 DOM 和日志工具节点全部在挂载时缓存。相同文本、宽度、`data-*`、`hidden`、`disabled` 与 ARIA 属性均跳过重复写入；150ms 状态合并不再执行 DOM 查询。
- 实时日志搜索以 100ms 合并窗口重绘最多 300 行；挂载 cleanup 会清理计时器和全部工具监听。平滑度滑块和历史图表 hover 使用共享动画帧调度器，同一帧只处理最后输入/坐标。
- 历史筛选每轮只派生一次任务列表，并把结果贯穿集合工作台、计数和摘要。200 条任务的全局、集合和配置搜索文本预先存入 `WeakMap`，连续搜索不再重复拼接和 lowercase 字段；刷新任务数组时整体重建索引。
- 历史图表按浏览器能力只绑定 Pointer 或 Mouse 一套事件；同一采样点内移动不重复写 tooltip/SVG，系统图表 marker 节点只查询一次。cleanup 会取消待执行帧并移除监听。
- 数据集编辑器只在首次从 synced 转为 dirty 时更新状态节点、禁用预览和同步 legacy bridge。行摘要只读取发生变化的当前行，并在 `input` 与 `change` 上即时反馈；稳定预设容器使用事件委托，搜索结果不创建禁用的行级拖放监听。
- 数据集路径工具在行重建/页面卸载时取消所有验证计时器、使在途结果失效并移除 input/copy/browse 监听。图片预览实现改为首次打开时动态加载，预览刷新按钮不再持有旧页面 state。
- 历史详情样张对话框拆分静态模板与交互控制器；近 10KB 的导航、键盘、复制和参数渲染代码只在“产物”页签加载。
- 历史详情概览不再解析图表模块或生成隐藏 SVG。`history-metrics-controller.js` 只在“指标”页签动态加载 Loss/LR 与系统图表模块，并为 314 个指标、977 个系统采样生成可见图表；离开详情时统一释放 hover、滑块和帧调度。
- 数据集图片预览由 `dataset-preview-controller.js` 按首次打开加载；未使用预览时首屏不再下载/解析 5.7KB 预览实现。

确定性运行时门禁：连续 100 次相同配置 DOM 更新不新增查询且各类 DOM 属性只写一次；20 次日志搜索只保留一个 100ms timer 并重绘一次；历史索引建立后连续 100 次搜索不再读取任务搜索字段；100 次指针移动只调度一帧并处理最后坐标；12 行数据集路径绑定卸载后 timer/监听均归零。

## 绝对内存基准

在 Codex 内置 Chromium 151、`127.0.0.1:20203` 下对五个目标路由分别执行 3 次独立冷标签采样。每次等待页面 `load` 后稳定 3 秒，再以 500ms 间隔读取 3 次对应 renderer 的 `/proc/<pid>/smaps_rollup` 并取中位数；下表再取三次冷启动的中位数。

| 路由 | DOM 节点 | RSS | PSS | 私有物理内存 | Swap |
| --- | ---: | ---: | ---: | ---: | ---: |
| 训练配置 | 3,925 | 77.01 MiB | 13.79 MiB | 6.27 MiB | 0 |
| 数据集蓝图 | 2,133 | 77.02 MiB | 13.79 MiB | 6.27 MiB | 0 |
| 实时训练 | 1,721 | 77.02 MiB | 13.79 MiB | 6.27 MiB | 0 |
| 历史列表 | 2,053 | 77.04 MiB | 13.81 MiB | 6.28 MiB | 0 |
| 历史详情概览 | 2,306 | 77.04 MiB | 13.79 MiB | 6.27 MiB | 0 |

这里的 RSS 会把共享 Chromium 映射完整计入，不能当作单标签新增物理内存；PSS 按共享比例分摊，更适合估算系统容量；“私有物理内存”是 `Private_Clean + Private_Dirty`，表示该 renderer 独占的常驻页。浏览器主进程、GPU、网络服务属于 Codex 内置浏览器的共享基础设施，无法可靠归因到单个 WebUI 标签，因此未计入表格。内置浏览器没有向页面暴露 `performance.memory`，本次不报告不可核验的 JS Heap 数字。

同一历史详情标签依次打开指标、产物、配置和 1,876 行日志后，日志态挂载 196 行、DOM 为 2,613 节点，renderer 仍为 76.61 MiB RSS / 13.32 MiB PSS / 5.78 MiB 私有内存，Swap 为 0。另在单标签内连续执行 50 次跨路由切换，初始配置页为 77.01 / 13.79 / 6.26 MiB，切换完成并空闲 15 秒后为 76.59 / 13.31 / 5.77 MiB，浏览器 Console 无 warning/error；在该测试分辨率下没有观察到导航累积增长。

## 剩余机会

1. `06-dragon-pages.css` 仍有约 132KB / 3,679 行，混合数据集、队列、权重分析、模型配置和图像测试等页面。下一轮应先按 selector 所属页面建立机械分区和跨页共享清单，再做搬家型拆分，不能只按行号切割。
2. 训练配置仍是五个目标中的最重脚本路由（36 个脚本）。训练预设库是当前布局中的首屏可见工作区；现有 8 个用户配置不足以证明虚拟化有收益，后续应先用大配置库基准决定是否投入。
3. `history-view.js` 已是详情专用模块，但文件名仍沿用旧兼容命名。后续可在统一更新测试和 cache token 时改名为 `history-detail-view.js`，本轮不为命名制造额外变更。
