# Anima FP16/BF16：200步配对训练与100/200步采样

日期：2026-10-02。状态：两路训练、16张采样图、240次固定验证均完成；
训练完整性独立审核通过。本轮未观察到FP16明显劣化，未执行完整质量认证。
范围：CMP 90HX 10GB（SM86）、Anima plain LoRA、一个配对seed、一个画风数据集。

## 结论

FP16与BF16各完成200次真实连续有效更新，零跳步，全部loss、更新和保存权重有限。
两路实际初始FP32 LoRA张量相同，AdamW初始状态相同，全部200步的数据、文本、noise、sigma身份一致。
最终实际AdamW的392个参数状态均为step200；不是只把global_step推进到了200。
FP16的native AMP初始scale1024，200步全程保持1024；保留FP32 adapter与residual/final保护。

共同BF16 evaluator上的200步验证MSE为FP16 **0.204031005**、BF16 **0.204082673**，
FP16比BF16低约 **0.0253%**。四组共16张采样图均成功生成；明牌查看200步四对图，
构图、姿态和细节有差异，未见明显FP16特有的画面崩坏。这不是正式盲评或用户验收。

本轮支持继续将旧native FP16视为实用训练候选。它没有提供90HX上的速度或显存优势，
该卡仍更适合BF16。严格梯度误差失败和实际训练可用性分开记录，不再用这次训练观察改判旧严格矩阵。

## 冻结配置与数据

- 单配对训练seed20261003，plain LoRA rank/alpha4，AdamW lr1e-4，constant scheduler，clip1。
- batch/accum1，torch attention，full checkpoint，swap20，关闭compile、自动swap与OOM重试。
- 保存100/200步BF16 LoRA与FP32训练state；BF16先运行并保存初始FP32 LoRA，FP16加载同一文件。
- 临时运行包装在采样边界使用独立CPU generator提供共同FP32 noise/sigmoid sigma，
  保持原flow-matching公式和各路径的模型入口cast；未改生产源码或默认配置。
- 同画风`style_8_4`选择16张训练图和8张留出验证图；4032/4200两个token family各train8、val4。
  图像、caption、latent和text cache均绑定哈希。24条文本缓存单次编码，保留512位置padding。
- 验证集与本轮训练集没有stem或图文内容重叠；排除三个已知既往探针样本，
  不声称这些留出图片从未参与用户历史训练。数据划分不根据本轮结果修改。

精度及配对取证只写每步标量和哈希，不保存200套完整梯度。
更新范数取证、张量哈希、CPU↔GPU同步等存在开销，下面步时不是未经取证的生产吞吐。

## 固定验证

每份adapter对相同8张验证缓存，覆盖sigma .2/.5/.8和noise seed20261011/12，
共48次预测；初始、BF16-100/200、FP16-100/200共240次。
canonical latent/noise先用FP32混合，noisy/timestep/prompt/padding在模型边界转BF16；
target为canonical `(noise-latents)` FP32，所有case的MSE等权平均。
保留完整文本padding，不裁剪，不更新参数，所有权重使用同一BF16 evaluator。

| 权重 | 验证MSE | 相对初始改善 |
| --- | ---: | ---: |
| 初始 | 0.204869860 | — |
| BF16 100步 | 0.204189633 | 0.3320% |
| FP16 100步 | 0.204142248 | 0.3552% |
| BF16 200步 | 0.204082673 | 0.3842% |
| FP16 200步 | 0.204031005 | 0.4095% |

100/200步的FP16/BF16验证MSE比值分别为0.999767937 / 0.999746826。
CPU收尾核验从240条原始记录用FP64标量重新汇总，与GPU worker的汇总一致；
每个case跨五份adapter的canonical与模型输入身份完全一致。
这验证了输入及汇总自洽，不是第二套模型独立重跑预测。

BF16相对初始只改善0.3842%，低于旧协议预设的0.5%改善信号。
本轮单seed200步不是旧三seed50步协议，旧门槛未在此重新套用或事后放宽；
小幅接近结果不认证长期收敛，也不证明两方案在所有训练任务上等价。
原始eval结果的`reference_only`字段未用于任何通过/失败判定，不是旧质量协议的完整实现。

## 实验完整性、封装缺口和验收

Luna分别启动文本缓存、两条训练及串行采样/验证；Sol独立审查启动包装和evaluator，
并用CPU独立核验真实200步训练、AdamW状态、文件哈希及配对身份，结果pass、exit0。
原生产训练数学、自动精度/OOM默认值、GPU功耗/风扇和另一张GTX1050均未修改。

三处封装问题如实保留：

1. 文本缓存官方CLI实际exit0、24 cached/0 skipped，但未提供公共monitor要求的result.json，
   supervisor因此error。24条实际缓存均逐条验证，没有重编码来掩盖该记录。
2. FP16的worker result和run_end均完成200步，所有真实更新/AdamW状态通过独立审核，
   但没有取得supervisor.json，外层退出码和外部监控完整性无法确认。
   483条原始遥测及全worker PyTorch峰值保留；外部资源峰值只是已采样值，不认证整段绝对最大值。
   后续采样在结果、run_end、已退出PID及GPU空闲等真实证据齐全后启动，没有重跑训练或伪造supervisor。
3. 后续队列脚本用`except BaseException`捕获了正常`SystemExit(0)`，把汇总误记为error。
   五个实际子阶段的退出码均0，16张PNG及240条验证记录均完整。
   原错误JSON和实际执行源码保留；另写`stages-verified.json`核验真实子阶段。
   仅修正后续脚本的异常捕获并做正常退出CPU回归，没有重新运行GPU阶段。

评估准备代理达到10分钟边界后由主代理停止并接手，补齐空间padding mask和导入路径；
保留旧eval-plan，GPU执行前冻结新plan，独立审查后才运行。
训练/评估数学CPU自检通过，队列正常退出回归通过；不需要重跑GPU或扩大无关测试。

本轮产物约640MB（汇总和展示图另增加少量字节），在4GiB预算内；
固定验证监控exit0、116条遥测无错误，GPU峰5088MiB，约123.9秒。
结束90HX返回17MiB、0%利用率。
