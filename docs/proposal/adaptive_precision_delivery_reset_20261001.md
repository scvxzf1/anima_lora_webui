## 判断

当前已有足够诊断设施，主要瓶颈是缺少有收益的可部署精度计划。
继续沿block17→K→head→token→反向恢复逐级解释，可以增加单样本机制证据，
却不直接产出普通Linear精度名单。应停止将完整根因解释作为工程交付前置条件。
原路线图第1节已经要求“不再把不断增加独立探针数量当作主要交付”。

真实进度按能力说明，避免把测试数量换算为完成百分比：

| 能力 | 当前事实 | 剩余核心工作 |
| --- | --- | --- |
| 硬件路由 | 已有BF16/FP16-islands/FP32能力初选 | 不等于数值自动校准 |
| 精度执行 | 原四组5步完成；旧AMP FP16五步更省更快，但集中12格严格0/12通过、证据自洽 | 按独立预登记协议评价质量；有实用收益的自动计划 |
| 搜索 | 12候选有界筛选、两个保留样本及非零AdamW状态验证完成 | 收益决策、身份绑定、计划桥接 |
| 日志/隔离/监控 | 批次结果、实际dtype与短训总报告已落盘 | 通用训练流程内的选择/拒绝总报告 |
| 启动OOM | 有界新进程、增加swap、结构/主机容量上限 | 与最终选定计划联合验收 |
| 更新后OOM | 生产result仍为committed_checkpoint=null | 数据游标/状态契约，不能冒充已交付 |
| 旧卡有效性 | 当前90HX可测试FP16数值路径 | Turing真实kernel、容量和速度仍须该硬件验证 |

源码证据：`training_config.py`/`training_precision.py`接受精确FP32名单；

## 第一批：直接回答是否存在有收益的Linear精度组合

复用现有probe/monitor/comparator，开发一个批次编排器，不再为每个问题新建独立driver。
固定来源权重、adapter、输入、RNG、后端、swap和loss scale；本批基线和候选使用同一版本。
只按普通Linear可部署配置进行干预，不替换参考激活，不改变模型数学。

候选起点采用FP32控制组，按块区间降精度。优先测试已有整网结果中偏差较小的MLP2，
不假定block17或早期层必然敏感，不假定层数越少越准确：

| 子批次 | 内容 | 新候选预算 |
| --- | --- | ---: |
| 控制 | FP32参考、同路径全FP32控制、BF16诊断对照 | 3个worker，非候选 |
| 首轮 | MLP2按blocks 0..6、7..13、14..20、21..27分别仅该组FP16 | 4 |
| 自适应轮 | 实测较好组的组合/细分或等计算量替代组 | 最多4 |
| 确认轮 | 复核较优方案或用少量其它高成本Linear组替代 | 最多4 |

先用已有sigma=.5固定状态做单案例筛选；它只是已知失败案例，不称普遍最坏sigma。
最多12个不同候选，每个组合均重新测整网；通过组的并集不能继承通过结论。
全部失败或只有几乎全FP32且无实用收益时，输出“当前Linear策略预算内不可行”，
结束此搜索方向，不自动追加逐层诊断或无限候选。

搜索保留现有prediction/梯度严格门槛和每个失败记录。按实测误差、参数字节、
计算时间与峰值内存选择候选集合；FP16模块数量不代表覆盖的计算量或显存。
若有f比例的冻结权重元素从FP32变FP16，理论权重payload下降f/2；
这不是GPU峰值下降比例，也不保证加速。权重/CPU masters/激活/交换分别记录。
候选先同swap比较，选定后才单独优化内存计划，避免混淆精度与swap的收益。

## 同批补齐一个重要指标：优化器更新

现有capture发生在clip之前，保存prediction/input-gradient/adapter-gradient；
TrainingReplay恢复adapter、buffers、输入与RNG，不恢复Adam moments/step。
`adapter_max_delta`是相对初始adapter的单一最大值，不能作同状态更新误差比较。

因此新增有界的更新对照：固定相同pre-step参数、optimizer moments/step、scheduler与
实际clip/epsilon/weight decay配置，比较本步delta向量，保留绝对量、分组相对量与余弦。
在副本状态执行，不能修改下一候选参考。初始零moments与非零moments分别标明。
该指标与旧梯度门槛并列，旧失败不改写为通过；不能用更新接近单独证明长期收敛。

现有BF16诊断对照最大adapter梯度误差68.328%，也超过2%门槛；其输入处理与生产BF16
并不完全相同。这个事实要求检查门槛与任务质量的关系，既不证明BF16生产失败，也
不证明门槛错误，更不能直接据此放宽阈值。
实际训练质量验收应另立预注册标准和生产路径BF16对照，保留严格诊断结果。

## 第二批：只让最有希望的1--2个候选进入泛化与训练

- 对新增两个真实缓存样本覆盖两种bucket，在sigma .2/.5/.8及初始/非零adapter状态
  交叉验证；每个样本所属bucket固定，共2×3×2=12个案例/候选。
- adapter状态与sigma独立变化，避免现有三步中两者同时变化的混淆。
- 代表集、保留集分开。新案例失败时给出范围和原因，不能对保留集无限调参。
- 先通过固定状态验证，再用实际train.py完成受限plain LoRA 3--5更新的链路验证。
  20--50步及生成质量评估单独制定数据、指标和预算；本计划不启动长训练。
- 同卡同条件记录预热后纯计算和端到端步时、allocated/reserved、GPU/RSS峰值、
  有效更新/跳步。没有速度收益就如实标注容量兼容模式，无容量收益也不包装成优化。

## 第三批：把选择结果接入用户工作流

已有精确FP32名单安装入口可复用，但不能直接信任任意selected-plan.json。
加载时验证model/family/adapter/代码实现/设备后端/精度配置/验证范围，并保存冻结计划。
训练结果目录新增一份总报告：候选、选择/拒绝理由、验证范围、收益、校准成本、实际dtype、
OOM尝试及终态。无候选时明确报告；允许现有FP32回退配置，但不将它计作FP16目标达成。

通用轮子的首版应是能力过滤、候选预算、评估接口、计划身份/缓存和日志schema，
Anima只负责模型语义分组；不先承诺所有模型拥有同一敏感层规律。
启动OOM可与此集成；更新后OOM数据恢复是独立工作流，不让它阻塞Anima精度首版，
也不因精度探测成功而开放中途恢复。

## 提高执行效率

- 以一个批次产出候选表和明确决策，用户不必逐个提示“继续”。
- 复用现有runner/监控/比较器；优先新增策略数据和少量helper，避免持续复制诊断driver。
- 同一批参考只录一次；修改probe数值逻辑后必须录新参考，旧SHA证据不回写。
- 重复递归source_evidence在多个层级加载和重算旧tensor，先加阶段计时再优化；
  同进程已验证不可变对象可复用，跨进程仍核验实际输入内容，不能只凭mtime跳过SHA。
- 关键实现一次独立验收；修正仅定向复测受影响契约；批次结束一次集成验收。
- 若代理额度不足，主代理直接接手，不反复创建/等待已满额度或复用被规则禁止的代理。

已有监控证据：同前向base-dx批次的整网单步reference/baseline/counterfactual分别
57.3/49.2/49.4秒；后续CPU激活分布164.0秒、局部K重放233.2秒。
这些不同任务耗时不能推算吞吐加速倍数，但说明研究粒度更细并不意味着决策成本更低。
新的批次需限制总候选数和端到端时间，并将初始化、SHA/IO、计算、审计分别计时。

## 复盘时的交付建议

最初复盘只完成报告/源码复盘并调整路线，未启动GPU或改变运行时；随后授权的批次1
已交付“有界候选表 + 同状态更新指标 + 一批完整筛选结果”，见本文件顶部状态。
当时要求下一交付为“有界候选表 + 同状态更新指标 + 至少一批完整筛选结果”，
而不是另一份token级机制报告。若预算内所有可部署候选失败，应明确技术瓶颈，
再评估FP16 GEMM保留FP32输出等新算子方案；普通F.linear后.float()并不提供该能力，
新算子还需覆盖反向/checkpoint/swap与Turing，不作为无验证的快捷修复。
