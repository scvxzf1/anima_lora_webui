## 1. 目标与已确认方向

帮助信息应让用户先知道“这个参数做什么、现在要不要改、什么情况下改”，再按需了解选项、限制和原理。

已确认采用 B 版“建议优先”的方向：

- 说明正文直接放在标题下，不显示“一句话”栏目名。
- 简短说明与高亮建议必填，选项、注意、进阶、相关参数按需展示。
- 枚举值显示中文名称，配置值作为辅助标注。
- 注意事项直接可见，进阶默认折叠，无内容不显示空栏目。
- 顶部保留当前值。与可确定的页面默认值不同时，标注“与默认值不同 · 默认 xxx”。
- 可恢复时提供“恢复页面默认值”；模型族显示为小标签，当前字段就是模型族时去重。
- 区分实现支持、界面允许选择和真机验证范围，不用一个“支持”覆盖三种含义。

已完成独立 A/B 概念预览，包含模型族、标注扩展名和低分辨率过滤。预览里的值与恢复操作仅为演示，未接入产品状态。
预览 VAE 解码的新版文案方向也已确认，但实际行为仍须按各模型族源码核对。

## 2. 范围与边界

本计划覆盖帮助数据结构、内容改写、弹窗展示、上下文状态、默认恢复、相关帮助导航及必要验证。
不改变训练算法、配置键、方法默认值、缓存格式或模型能力。发现实际行为缺陷时另列问题，不靠修改帮助文字掩盖。

首批样板为四个字段：

| 字段 | 类型 | 重点验证 |
| --- | --- | --- |
| `model_family` | 枚举 | 按底模选择、模型族去重、能力表述边界 |
| `caption_extension` | 输入 | 短文案、文件示例、JSON 标注的适用条件 |
| `drop_lowres_images` | 开关 | 开关建议、像素总数示例、关联 `min_pixels` |
| `sample_vae_decode` | 性能选项 | 中文选项、显存与耗时取舍、按模型族核对回退顺序 |

第二批用学习率、`network_dim`、`blocks_to_swap` 和编译相关字段验证数值型与复杂联动场景，再展开全量迁移。
准确字段键与范围在内容盘点时从当前目录确认。

## 4. 内容与数据契约

### 4.1 写作规范

- 面向用户用“你”，先给操作结论，再解释适用条件。
- 每个自然段最多两句话，避免靠分号拼接长句。复杂信息拆成表格或短列表。
- 数值建议标明成立条件，不把经验值写成对所有模型、显卡和数据都适用的最优值。
- 术语首次出现时作简短解释，不影响选择的内部细节放进进阶或完整文档。
- 枚举说明回答“什么时候选”，数值说明回答“调高或调低会怎样”。
- 风险必须具体到触发条件和后果。“无明显代价”“请谨慎使用”不作为填充内容。
- 普通建议与不可用原因分开。已禁用字段仍显示其真实不可用原因。
- 信息不足时明确缺少哪部分说明，不生成缺乏依据的推荐值。

### 4.2 新帮助结构

建议采用具名对象，具体模块名在 P1 确定：

```ts
type FieldHelpV2 = {
  summary: string;
  recommendation: string;
  options?: Array<{ value: string; when: string; detail?: string }>;
  guidance?: Array<{ title: string; paragraphs: string[] }>;
  cautions?: string[];
  advanced?: Array<{ title: string; paragraphs: string[] }>;
  relatedKeys?: string[];
};
```

`guidance` 用于“什么时候关闭”“怎样判断图片太小”等必要说明，不成为新的必填模板。
选项名称优先复用表单目录，帮助只补充选择条件；未知或旧配置值原样可见，不伪装为合法默认值。

文案保持纯数据，不存 React 节点、任意 HTML、表单回调或直接执行的表达式。
按模型族变化的内容由小型解析层选择，避免在所有段落中重复条件分支。
实际可选项和禁用原因来自当前表单能力逻辑，不另建一套支持矩阵。

维护侧登记事实来源、核对日期和验证范围，放在内容清单或邻近说明中，不作为用户弹窗的固定栏目。
摘要应由同一份内容生成或导出，具体方案须兼顾当前按需加载，不能为去重而让主页面提前加载全部长文案。

### 4.3 交互契约

| 场景 | 行为 |
| --- | --- |
| 当前值等于页面默认值 | 只显示当前值，不显示重复默认值 |
| 存在明确默认值且当前值不同 | 显示差异标记；具有安全编辑能力时提供恢复 |
| 默认值未知、依赖上下文或字段只读 | 不猜默认值，不提供不可执行的恢复按钮 |
| 模型族字段 | 当前值已表达模型族，不再显示同内容标签 |
| 相关参数 | 默认在帮助内切换条目并可返回，不直接改参数或切模型 |
| 定位表单字段 | 若提供“定位字段”，显式触发，复用筛选/阶段切换和焦点逻辑 |

当前值比较使用字段的有效类型语义，保留 `false`、`0`、空字符串、未设置值的区别。
默认来源和恢复操作由编辑器提供。模型族、嵌套 network 参数、别名和缺省删除必须走既有更新路径。
恢复只修改草稿，不保存、不提交队列、不启动训练，也不同时修改其他无关字段。
确有既有联动时，应展示影响说明，并遵循原有联动契约。

## 5. 分阶段实施

依赖顺序：P0 → P1 → P2 → P3 → P4 → P5。
P4 的源码核对和文案准备可在 P2/P3 期间按独立领域开展，合入仍以数据契约稳定为前提。

| 阶段 | 主要交付物 | 完成条件 |
| --- | --- | --- |
| P0 盘点与事实核对 | 字段清单、类型分类、来源记录、首批终稿 | 四个样板的行为和默认语义均有当前依据 |
| P1 数据契约与兼容层 | V2 类型、旧数据适配、内容解析入口 | 新旧条目可共存，键和摘要无遗漏 |
| P2 新展示与首批样板 | B 版弹窗、四个样板、可读状态栏 | 新结构可用，键盘和窄屏交互正常 |
| P3 表单交互接入 | 恢复页面默认、相关帮助导航与返回 | 恢复语义正确，导航不丢草稿和上下文 |
| P4 分批改写与扩展 | 全部范围内条目迁移、维护清单 | 无未核对迁移项，复杂参数可被新结构承载 |
| P5 集中验收与收尾 | 验收证据、兼容清理、维护说明和构建 | 内容覆盖、关键交互、发布构建满足门槛 |

### P0：盘点与事实核对

1. 对账帮助条目、字段目录、枚举、默认值和摘要，登记缺失、重复、已退役、模型族专属条目。
2. 按枚举、开关、数值、路径/文本分类，标记高风险建议与跨参数依赖。
3. 核对首批字段的当前源码和已有测试，记录相关文件或符号。
4. 对 `sample_vae_decode` 按模型族核对可选值、别名、解码设备、异常类型及回退顺序，不能把截图中的顺序直接外推到全部家族。
5. 确定页面默认、baseline、继承值的显示和恢复规则，给出正常、不同默认、未知默认、不可用四类样例。

验收：首批文案能够回答“怎么选、何时改、真正的限制是什么”；未确认的机制有明确待核对项，不进入正式断言。

### P1：数据契约与兼容迁移

1. 增加 V2 类型与统一解析入口，旧条目通过临时适配器继续可读。
2. 适配器只负责承接旧内容，不能把旧 `fill` 自动标成“原理”，或把所有旧“好处”直接提升为建议。
3. 尚未重写的旧段落可作为临时详细说明保留，真正的风险保持可见，禁止迁移时静默丢失信息。
4. 决定摘要同源方案，保留现有调用方和按需加载接口。
5. 保持渲染器、内容解析、数据分册边界，避免将文案和联动逻辑堆入弹窗组件。

验收：四个样板可用 V2 表达，未迁移字段保持可读，现有键和摘要一致性检查通过或有合理更新。
该阶段以行为保持为主，不同时重写全部内容。

### P2：新弹窗与四个样板

1. 落实说明正文、高亮建议、选项表、注意、折叠进阶与上下文去重。
2. 首批四字段接入正式数据，用原有产品样式系统实现，不把独立预览的演示代码直接复制为业务组件。
3. 保留不可用原因、关闭、遮罩、Esc、焦点约束与关闭后焦点恢复。
4. 适配长配置键、长选项内容、窄屏和当前支持的主题，避免横向溢出。
5. 此阶段尚未接好的恢复和跳转不显示假按钮。

验收：首屏先给出解释和建议，空栏目消失，选项可理解，关键限制不依赖展开才能看见。
首批只代表结构和内容样板完成，不代表全量帮助已迁移。

### P3：恢复默认与相关帮助导航

1. 将编辑器已解析的默认来源、当前状态和恢复能力显式传入，弹窗不读取全局表单或自行写配置。
2. 保留现有“撤销到 baseline”，新增动作只表达“恢复页面默认值”。
3. 对普通值、`false`/`0`、缺省值、别名、嵌套参数和模型族联动做定向验证。
4. 相关参数显示中文名和配置键，维护帮助内返回栈，支持返回原条目及合理保留阅读位置。
5. 目标字段不在当前表单时可以只读查看帮助；失效键不渲染为可点击链接。
6. 如增加定位表单动作，验证筛选隐藏、阶段隐藏、特殊字段节点和弹窗关闭后的焦点时序。

验收：没有自动保存或训练副作用，导航不改草稿，恢复产生的结果与编辑器契约一致。
涉及配置兼容语义的关键检查由非实现者独立核验，未通过的动作不作为已完成能力交付。

### P4：按领域批量迁移

| 批次 | 内容 | 核对重点 |
| --- | --- | --- |
| 第一批 | 学习率、rank、块交换、编译等复杂样板 | 数值建议的前提、模型族差异和参数关联 |
| 第二批 | 数据集、标注、过滤、路径 | 来源优先级、格式、缓存重建与缺失文件行为 |
| 第三批 | 常用训练、保存、采样与预览 | 训练与预览边界、恢复兼容、耗时与显存取舍 |
| 第四批 | 优化器、网络变体、实验和高级配置 | 实现支持与验证范围、特定方法下是否生效 |

每批先核对当前实现，再改写并审阅关键差异。任务按文件或独立分册分配，避免多人同时编辑同一大文件。
每批更新清单中的“已核对、已迁移、已验收、待澄清”状态；结构迁移和事实核对不能互相代替。
批次大小按内容风险调整，不强制以一次重写固定数量为目标。

验收：范围内条目全部有明确去向，必填内容完整，可选栏目有实际价值，相关键和枚举值可解析。
覆盖以当前字段集合为准，不以凑齐 263 作为唯一完成条件。

### P5：集中验收、清理与发布准备

1. 检查普通、禁用、未知值、缺少帮助、不同模型族和不同默认值等代表场景。
2. 完成关键交互验收、类型检查和构建，保留实际执行命令及结果。
3. 全量迁移且调用方无旧依赖后，删除临时适配器和七参数 builder 的废弃接口。
4. 更新前端维护说明，明确新字段帮助的新增方式、摘要同步方式与事实来源核对要求。
5. 将稳定用户说明放入合适的功能文档；完成后按仓库约定归档本计划。

验收：没有遗失的条目和重复事实源，生产构建可用，未验收项和适用限制已记录。
发布按现有 Git 与前端构建流程执行。本计划的制定不自动授权提交、推送或替换用户正在访问的部署。

## 7. 风险、回退与协作

| 风险 | 处理方式 |
| --- | --- |
| 旧模板语义错误随迁移保留 | 兼容适配不算文案验收，逐条核对并显式标记进度 |
| 帮助与实时能力漂移 | 复用枚举/禁用来源，按模型族核对事实，避免手写重复能力表 |
| 恢复误当撤销、误覆盖关联值 | 操作命名明确，复用编辑器更新路径，关键契约独立验收 |
| 导航扰乱表单筛选或草稿 | 帮助内阅读与定位表单分开，显式定位才改变视图 |
| 模板重新膨胀 | 保持两项必填，拒绝无意义栏目和全部字段统一长表格 |
| 全量一次替换难以回退 | 按阶段和领域拆分可审阅变更，旧适配器保留到迁移完成 |
| 工作区并发改动 | 尊重已有差异，明确文件归属，并行写入用独立工作树 |

数据契约和共享渲染由一个责任人集成。独立文案领域可并行核对，关键表单行为交由不同人员或代理验收。
实际修改者阅读即将修改的原文，集成者审阅关键差异与证据，不重复通读所有材料。

回退以撤销本次独立变更或恢复上一份已验证构建为单位，不使用硬重置、清理用户目录或改写共享历史。
即使展示回退，也不撤回用户在草稿中已完成的正常编辑。
