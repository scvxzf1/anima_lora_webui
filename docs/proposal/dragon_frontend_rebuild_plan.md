# Dragon 新前端开发计划书

- 状态：已实施 / 独立入口验收中 / 默认切换待批准
- 编写日期：2026-09-09
- 版本：v1.1
- 适用范围：Dragon WebUI 前端重建，复用现有 aiohttp 后端与用户数据
- 核对基线：`dev`，HEAD `2e96bd0ce3a7c2803d542e5b0b7dfeac77369d8b`，含大量未提交改动，不是线上纯净快照

## 1. 决策摘要

本轮已经确认的方向：

- 重新设计和构建业务界面，不在旧 Dragon 页面上继续叠加一套装饰样式。
- 整体结构参考 FocusFlow：分组导航、对象列表、主工作区、按需出现的详情面板。
- 监控信息层级参考 Zaptix：紧凑状态摘要、主要趋势区、辅助资源指标。
- 技术主线采用 React + TypeScript + Vite + shadcn/ui + Tailwind CSS。
- 复用现有 aiohttp API、训练服务、配置目录、队列、历史和打标服务；不重写训练内核。
- 保留 classic 与现有 Dragon 的兼容入口，先在隔离入口验证，再决定默认切换。

本计划的新决定与待验证项：

- 以已有 `web/frontend-next/` 作为工程承载位置，重建其页面壳和业务交互，而不是创建第三个 React 工程。
- 现有 API adapter、类型、状态和测试逐项审计后复用；“已经存在”不代表功能完整或已验收。
- 首批设计验证页为训练参数、队列、打标审阅；不能只凭首页效果决定整站。
- 先按本计划默认方案实施，细节在阶段门禁中确认；交付周期是估算，不是固定日期承诺。

“从头构建”指新交互和新组件体系，不指删除已经验证的业务规则、配置字段或用户文件。
本文保留设计决策与门禁；实施状态见第 8.3 节及
[实施与验收记录](../features/dragon-next-implementation.md)。构建前端不等于批准启动真实训练或切换默认入口。

## 2. 目标与非目标

### 2.1 目标

1. 配置、数据、任务和结果具有一致的对象选择与详情查看方式，减少跨页丢失上下文。
2. 参数工作台可以承载完整适用字段，支持搜索、条件披露、修改摘要和错误定位。
3. 长时间运行时，状态、日志、图表和队列可恢复、可追踪，不被前端断线误报为训练失败。
4. 八个主要页面及关键子流程均有明确的功能对账与测试证据。
5. 新模块具有单一职责，避免重新产生超大页面、全局状态总线和隐式 DOM 耦合。
6. 生产环境继续通过 Python 服务访问，普通用户不需要额外运行 Node 服务。

### 2.2 非目标

- 不新增训练算法、模型族或新的 GPU 调度引擎，不改变 compile、cache、adapter 能力边界。
- 不引入 Next.js、SSR、独立 Node BFF、微前端或新的用户账号系统。
- 不把训练配置、数据集、历史、模型库的不同分组强行合成一个持久化“项目”实体。
- 不自动迁移配置根、模型、图片、标注、缓存、训练结果或历史目录。
- 不为了设计完整而擅自增加批量删除、自动写回、自动下载或自动训练行为。
- 不复制 Behance 作者的品牌、图片和展示包装；参考不等于获得设计资源再分发授权。

## 3. 当前工程事实与处理方式

以 [功能图谱](../features/dragon-ui-functional-map.md) 为业务清单起点，再以实时源码核对。
图谱采集于 2026-09-08，旧专题文档与当前实现可能存在差异，不能将旧描述直接当作新版本规格。

| 已核对的事实 | 本计划处理方式 |
| --- | --- |
| `web/frontend-next/` 已使用 React、TypeScript、Vite、React Router、TanStack Query、Zustand、React Hook Form、Zod、Lucide 和 dnd-kit | 保留工程边界；M0 审核依赖、安装和构建可复现性，不盲目整体升级 |
| React 路由已有 datasets、training、queue、monitor、history 和 history detail | 五个模块全部重新对账，不能以路由存在替代完整功能验收 |
| 当前 React 工程未声明 Tailwind/shadcn 依赖 | M1 建立组件底座与主题 token，不将现有 CSS 全量搬入 |
| React Router 使用 `/next` basename；当前根路由跳转到 datasets | 保留已有业务深链，计划将新入口默认落到 training；在 M1 验证 |
| aiohttp 已提供 `/next` 与子路径入口，构建文件位于 `web/static/dragon-next/` | 延用隔离入口，早期不改 `/?ui=dragon` 与 `/?ui=classic` |
| Vite 当前开发代理固定指向 20203，常规后端默认端口为 20102 | M0/M1 改为显式可配置的代理目标，并测试 HTTP 与 WebSocket；不假定某端口有可用服务 |
| 当前 WebSocket 重连有退避，但没有可直接依赖的游标重放机制 | 新连接成功后通过 HTTP 重新获取状态，不宣称消息天然可靠或绝不丢失 |
| 旧 Dragon/classic 由独立 bootstrap 与 DOM/CSS 系统运行 | 新 React 运行时不得依赖旧页面挂载、全局变量或旧 DOM id |

当前工作树有源码、配置及用户数据相关的未提交变化。计划编写时只新增计划和索引；实施继续保留这些变化，未执行 pull、切换、清理或暂存。
实施 M0 时先记录需保留的基线和差异，按仓库 Git 规则安全同步 `dev`，再建立隔离分支；不能只检出上述 HEAD 而丢掉本计划依赖的工作树内容。

## 4. 视觉与交互规范

### 4.1 参考来源

| 参考 | 借鉴内容 | 不照搬的内容 |
| --- | --- | --- |
| [FocusFlow](https://www.behance.net/gallery/250105067/FocusFlow-Branding-UX-UI-Dashboard-Design) | 多栏工作方式、列表与详情关系、分组导航 | 绿色光晕、大块渐变、低对比度细字、过多卡片 |
| [Zaptix](https://www.behance.net/gallery/226381751/Zaptix-EV-Charging-SaaS-UX-UI-Dashboard-Design) | 运行状态层级、主要趋势和辅助资源的比例 | 地图、展示用仪表、橙色整屏背景和设备样机包装 |

以上是在上一轮实际浏览的设计参考，不是经过交互验收的应用。新界面布局须用本项目的真实字段与脱敏样本验证。

### 4.2 统一工作台结构

```text
应用导航 | 当前页面的对象列表 | 主工作区 | 按需详情/检查面板
                 页面标题与对象级操作靠近主工作区
                 保存/预检/启动等命令明确显示作用对象
```

- 应用导航负责页面切换，对象列表负责当前页选择，不能将两者合成一棵语义混乱的树。
- 右侧检查面板不是永久第四栏；训练参数优先保证编辑宽度，打标审阅优先保证图片宽度。
- 页面主体采用连续工作面和分隔线，不把每个章节做成漂浮卡片，更不嵌套卡片。
- 原图、样张和预览图是业务资产，保留可检查的清晰度与比例，不用装饰图代替真实产物。
- 保留模型族、配置文件、数据集和当前运行任务的区别；正在编辑的配置不冒充正在执行的配置。

### 4.3 主题、密度与响应式

| 项目 | 计划默认值与约束 |
| --- | --- |
| 主题 | 中性炭灰暗色为首版默认，同时交付浅色；两种主题共用结构和语义 token |
| 色彩 | 中性灰为工作面，青绿用于主要操作，蓝用于选择/信息，黄与红用于警告/危险；不同状态兼有文字和图标，不只靠颜色 |
| 字体 | 中文优先系统无衬线；路径、配置键、日志和需要对齐的数字使用等宽/等宽数字，不依赖外部字体 CDN |
| 字号 | 正文默认 14px，辅助文字 12px，页面标题 20px；不使用随视口宽度变化的字号，字距为 0 |
| 控件 | 桌面默认高度 36px、紧凑模式不低于 32px；触屏主要目标至少 44px；卡片圆角不超过 8px |
| 宽屏 | 1600px 及以上按需展示对象栏和详情栏；对象栏建议 240-280px，详情栏建议 300-360px |
| 普通桌面 | 1280-1599px 保证主工作区，详情改抽屉；不得挤压长路径输入框 |
| 平板 | 768-1279px 导航与对象栏可收起，主体以单工作面为主 |
| 手机 | 低于 768px 单列，列表/详情逐层进入，操作区可换行；表格允许局部横向滚动，页面不整体溢出 |
| 动效 | 只用于必要反馈，约 120-180ms；支持 reduced motion，不做视差、背景光晕或常驻动画 |

上述值是待 M2 验证的设计 token 起点。浏览器缩放和已有全局/分页面缩放须单独验收，不能把两者连乘后导致内容不可访问。
保留旧缩放偏好，不清空旧存储；新页面使用显式映射和边界检查，在极端缩放下允许正常滚动，不承诺所有内容同时占一屏。

### 4.4 交互完整性

- 工具按钮使用 Lucide 图标，具有中文可访问名称；不常见图标同时提供 tooltip，危险命令使用明确文字。
- 所有可写页面都有未修改、已修改、保存中、保存失败、冲突和离开保护状态。
- 表单控件与 label 关联，错误可聚焦；模态层支持焦点圈定、Esc 和关闭后焦点恢复。
- 拖拽排序同时提供菜单或上下移动替代，不把鼠标拖拽作为唯一入口。
- 长名称、长路径、多行 caption、空值、中文输入法和数值中间输入态属于正常测试输入。
- 固定顶栏、底栏不能遮挡焦点和错误字段；DOM 顺序与视觉/键盘顺序一致，不用 Masonry 重排参数。
- 不新增介绍产品功能或教用户操作的大段页面文案；已有字段帮助、风险确认和错误原因继续保留。

## 5. 技术架构

### 5.1 技术选择

| 层次 | 选择 | 使用边界 |
| --- | --- | --- |
| 应用 | React + TypeScript strict + Vite | 独立 SPA，路由懒加载，不增加生产 Node 服务 |
| 路由 | React Router | 延用现有方案，统一应用壳、错误边界、深链和草稿离开保护 |
| 控件与样式 | shadcn/ui + Tailwind CSS + CSS variables | 选择一种底层 primitive 实现并固定；生成组件作为本仓源码审阅，不随意混入第二套 UI 框架 |
| 服务端状态 | TanStack Query | 管理读取、失效和缓存；不承载未保存表单草稿 |
| 表单 | React Hook Form + Zod | 本地输入校验和字段状态；后端校验仍是最终权威 |
| 跨页上下文 | 小范围 Zustand store | 配置选择、GPU 选择与必要 UI 偏好，不镜像全部服务端对象 |
| 图表 | ECharts，按需导入 | Loss/资源/历史对比；不在首包加载全部图表 |
| 大列表 | TanStack Table / Virtual，按需引入 | 队列、历史、长日志和图片列表达到规模后使用，不默认虚拟化整个参数表单 |
| 排序与图标 | 现有 dnd-kit + Lucide | 复用依赖，补键盘排序，不另造图标系统 |
| 测试 | Vitest + Testing Library + Playwright | 单元、行为、浏览器工作流与视觉回归；保留 pytest 后端契约测试 |

依赖版本以实施时的可安装性、兼容性及 lockfile 为准；现有 `package.json` 中的版本声明不是“已成功安装”的证明。
M0 核对 Node/pnpm 版本并固定项目工具链，提交 lockfile，CI 使用 frozen lockfile。禁止为完成界面一次性升级全部依赖。
React Flow、富文本编辑器和复杂动画库不进入基础依赖，实际需求成立后另立小决策。

### 5.2 目录与依赖方向

以下是目标职责布局；保留现有目录中通过审计的文件，不要求一次性机械重命名。

```text
web/frontend-next/
  src/
    app/                  路由、Provider、应用壳、跨页上下文
    api/                  HTTP client、错误协议、基础 DTO 校验
    components/
      ui/                 基础控件及其本地适配
      workspace/          对象列表、详情面板、动作栏等通用工作台组件
    features/
      training-config/    字段目录、规则、草稿、预检和训练动作
      dataset-editor/     蓝图、数据组、保存/应用、图片预览
      live-monitor/       实时连接、状态合并、图表与日志
      training-queue/     队列记录、调度策略、排序与重试
      training-history/   检索、集合、详情、产物与续训
      model-config/       模型组合与 revision 保存
      captioning/         来源、接入、任务、审阅、显式写回
      settings/           路径、显示与兼容偏好
    styles/               token、基础样式、布局约束
    test/                 脱敏 fixture、测试 Provider、网络 mock
  e2e/                    新界面的浏览器用例（计划新增）
```

依赖方向为 `app -> features -> api / shared components`；共享层不反向 import 业务页面。
跨 feature 通过明确导出的命令、类型和路由上下文协作，不读取其他页面内部组件或 DOM。
每个较大 feature 再拆 `api / model / hooks / components`，页面只组合视图，不承担序列化和业务策略。

### 5.3 规模控制

八个业务页、子页和测试不可能在 1000 行内完整重建。初步预算为手写生产源码约 12,000-20,000 行，
测试约 6,000-10,000 行；不含现有可复用代码、lockfile 和按需生成的基础控件，M0 对账后重估。
这不是产出行数目标，能复用并缩小实现时优先缩小。

- 单次实现切片尽量控制在约 1000 行新增业务代码以内，大切片先继续拆分。
- 单组件建议不超过 200-300 行，单函数建议不超过 80 行；单文件接近 600 行启动拆分评审，避免超过 1000 行。
- `App`、router、Provider 和全局 store 不接收具体领域逻辑。
- 旧 chunks 只允许必要兼容修复，新功能不得回流；禁止新增隐式 `globalThis` 状态总线。
- shadcn 生成代码同样需要维护，不能用“第三方生成”掩盖无法解释的重复和改造。

## 6. 状态与数据契约

### 6.1 状态所有权

| 数据 | 真相源 | 前端规则 |
| --- | --- | --- |
| 配置、模型库、数据集、队列、历史 | 后端服务与磁盘 | Query 缓存仅为快照，不冒充已保存结果 |
| 表单草稿 | 当前资源的独立表单状态 | baseline 与 draft 分离；后台刷新不覆盖 dirty 草稿 |
| 当前配置/覆盖预设/GPU | 轻量上下文 store | 与正在运行的任务分离；跨页传递不自动写盘 |
| 筛选、排序、任务深链 | URL 优先 | 可返回并恢复；路径和参数由 router 负责编码 |
| 主题、密度、面板开合 | 有版本的 UI 偏好 | 仅持久化非敏感偏好，不存 provider 密钥与完整业务草稿 |
| 实时运行状态与日志 | HTTP 快照 + WebSocket 增量 | 连接中断标记数据陈旧，不能自行推断训练停止 |

Query key 至少区分资源类型、资源标识、配置上下文和运行覆盖。配置根变化时取消旧请求、清理相关缓存与无效选择，
再重新读取；存在未保存草稿时先处理草稿。异步返回须校验当前资源身份，防止快速切换后旧响应写入新页面。

### 6.2 配置编辑与保存

1. 加载时同时保留原始配置、合并后的有效值、字段来源及可用的版本信息，不用 UI 默认值替代后端合并结果。
2. 动态字段隐藏只改变显示，不丢弃值。React Hook Form 配置为卸载不自动清除字段，并在领域模型中保留完整 baseline。
3. 以明确修改的键生成 patch；区分未设置、空字符串、`false`、`0`、数组及显式删除，不用 truthy 判断。
4. Zod 校验不得静默剥除未知配置键；兼容字段和原始 `network_args` 保留在独立原始数据层。
5. 配置键、字段 owner、顺序、条件披露和序列化映射有可对账目录；默认值和模型能力不在前端复制第二份权威表。
6. 审计经验证的旧规则时，可通过不依赖 DOM 的适配层复用；若必须抽取共享纯模块，应单独提交并同时验证新旧调用方。
7. 旧配置中的隐藏非默认值与隐藏 dirty 值可发现、可查看；preflight 错误能打开对应字段，不能指向不可到达的控件。
8. 保存、预检、入队和启动仍遵守“先成功保存草稿，再执行动作”；预检不是绝对只读。保存失败立即阻断后续动作。
9. 保存请求与响应对应固定 draft 版本；若保存中又发生编辑，仅推进已保存 baseline，不清空后续修改。
10. 保留现有只读/锁/revision 机制。接口缺少原子冲突检测时明确登记缺口；读取后比较不能宣称解决了并发覆盖，补后端能力需单独评审。

四阶段保留为 `输入准备 -> 方法配置 -> 训练计划 -> 资源与预检`，它们是导航定位而不是强制下一步向导。
不重新引入“新人/专家等级”决定能力；当前字段全集由实时目录生成，不硬编码 215、218 或其他历史数量。
参考 [渐进披露提案](dragon_config_progressive_disclosure.md) 的数据保留约束，遇到能力陈述冲突以实时后端与定向测试为准。

### 6.3 有副作用动作

| 操作 | 不可改变的语义 |
| --- | --- |
| 保存数据集 / 应用到训练 | 前者写蓝图，后者更新训练引用；有草稿先保存，不自动训练 |
| 快速选择模型 | 复制模型族与组件路径到草稿；不是持续绑定默认模型库 |
| 加入训练队列 | 当前训练页请求保留 `start_paused: true`；排队配置冻结，不追溯更新源 TOML |
| 暂停队列 / 停止训练 | 暂停后续调度与停止当前进程是两个命令，确认内容分别说明影响 |
| 队列重试 | 克隆冻结运行配置，不读取后来修改的源配置 |
| 清理队列记录 / 删除分组 | 不等于删除历史、图片、日志或权重 |
| 历史续训 | 使用历史快照和有效 checkpoint 创建新记录，不覆盖来源任务；不混同权重热启动 |
| 保存打标候选 / 写回 TXT | 候选保存与磁盘写回分开；切页不取消打标，重启丢失未写回候选的边界保留 |
| 更改全局根目录 | 改变后续读写范围，不自动迁移已有文件 |

训练启动、排队、续训、下载和写回不得由页面加载、effect、自动重试或 WebSocket 恢复触发。
命令执行中阻止重复提交；超时后的结果视为未知，先查询后端核对，不自动重发非幂等请求。
若现有 API 无法可靠识别是否已提交，显示不确定结果并交由用户确认，不伪造成功或失败。

### 6.4 实时连接、日志与认证

- 使用已有 `/ws/training`，规范化 `status / progress / log / system / queue` 等实际事件；未知事件不直接崩溃页面。
- 一个应用级连接分发给订阅者，组件只订阅需要的数据；卸载清理订阅，避免每页重复建连。
- 首次加载和每次重连成功后补取 status、queue、metrics/logs 等当前视图需要的 HTTP 快照。
- 快照与增量的竞态通过连接代次、资源身份和实际可用的时间/序号处理。M0 核对日志接口是否支持 offset/limit；没有可靠标识时重新替换窗口，不虚构去重保证。
- 断线期间使用有上限的退避；隐藏页暂停非必要轮询，恢复可见后刷新。终止态仍以服务器确认结果为准。
- 日志限制内存窗口并虚拟化，历史完整日志按需读取/下载；图表以有界窗口/降采样显示，不让 DOM 随训练时长无限增长。
- 复用已有服务端认证；HTTP 与 WebSocket 都测试未认证、过期和重新认证，不削弱非 loopback token 要求。
- 同源生产请求优先沿用已有安全 cookie；不把令牌写进 bundle、业务日志或 localStorage。开发代理需核对 cookie 路径与 WS 转发。
- provider 调用留在服务端；设置页不回显既存明文密钥、不持久化输入凭据，用户提交后清理敏感表单状态。
- caption、日志、配置文本和模型元数据按不可信文本渲染，禁止未净化 HTML；图片/下载路径继续由后端边界检查。

## 10. 构建、迁移与回退

### 10.1 构建和发布产物

1. 开发使用 Vite 本地服务代理同一套 aiohttp API/WS，目标地址可配置，不主动复用未知端口上的进程。
2. CI 使用固定工具链和 lockfile 生成静态产物；后端与前端以兼容版本一起发布，不要求最终用户启动 Node。
3. 保留 `/next` history fallback；资源 URL 使用独立 base，并验证刷新、错误资源、下载与认证。
4. 新产物先在临时目录完成构建和检查，再发布；不得清理 `web/static` 的其他文件或用户数据。
5. 资源采用构建 hash；入口与缓存策略协调更新。旧 HTML 引用的 chunk 在过渡窗口内可访问，避免发布期间动态导入 404。
6. 新旧应用分文档加载，不同时挂载两个 router；Tailwind reset 和主题变量不污染旧 Dragon/classic。
7. 源码安装与打包发布各写一条可复现路径，验证离线运行不依赖 CDN；是否分发 source map 在 M6 明确。

### 10.2 切换策略

- 阶段 A：开发/预览仅使用 `/next`，原默认入口不变。
- 阶段 B：八页核心闭环通过后提供明确的新界面入口，允许用户选择试用，不改已有偏好默认值。
- 阶段 C：对账、真实使用验收与回退演练完成，经用户批准再调整默认入口，保留显式旧模式参数。
- 未完成原生迁移的辅助工具通过全页跳转进入旧界面，跳转前处理草稿，不在 React 内嵌旧页面运行时。
- 旧浏览器上下文仅按白名单迁移有效选择与偏好；遇到不存在资源给出重选入口，不静默创建文件。
- 新偏好使用版本化命名空间，迁移不得清空整个 localStorage，也不得覆盖旧界面的偏好。

### 10.3 故障回退

- 路由或 lazy chunk 加载失败时保留错误边界，提供重试与旧界面入口；dirty 草稿存在时不自动整页重载。
- 新界面未加载时提供不依赖 React 成功启动的恢复链接；认证失败先处理认证，不伪装成资源故障。
- 回退仅切换前端入口/静态产物，不重启或停止训练服务，不清空队列，不恢复或改写业务数据。
- M7 演练覆盖缺失 chunk、API 不兼容、认证失效和切回旧入口，记录实际命令及结果。
- classic 与旧 Dragon 的删除或归档不在本计划的自动收尾范围，须另行批准并有引用/功能对账证据。

## 11. 风险与处理

| 风险 | 处理与阻断条件 |
| --- | --- |
| 工作树变化使文档过期 | 每阶段更新基线，先比差异；不把固定 HEAD 或旧字段数量当成全部事实 |
| 新界面只覆盖常用项导致丢功能 | 逐功能、逐字段对账；缺口未批准不切默认 |
| 现有 React 工程隐藏缺陷被直接继承 | M0 独立构建/测试基线，模块分别标注可复用、待补齐、重建 |
| 不完整能力元数据迫使前端硬编码 | 暂接经过测试的规则；补能力 API 单独评审，不从其他 capability 推断 |
| 表单刷新、卸载、隐藏导致数据丢失 | baseline/draft 分离、完整值层、资源身份门禁和 round-trip 测试 |
| 超时重发造成重复训练或写回 | 非幂等 mutation 禁止自动 retry；结果未知时核对服务器 |
| 视觉参考不适合大量中文参数 | M2 用完整字段和长路径验证，密度不合格先调整布局而非删字段 |
| 并发写覆盖或 WS 消息缺失 | 保留现有保护、补缺口；未解决前限制相关写操作或不进入发布门禁 |
| 新样式/构建污染旧入口 | 独立文档、样式和静态目录，旧入口回归与发布切换测试 |
| 重建范围持续扩大 | 八页与辅助工具分层；新算法、持久化打标任务、统一项目模型等另开需求 |
