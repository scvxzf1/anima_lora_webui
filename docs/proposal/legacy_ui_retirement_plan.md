# Classic / Dragon 旧 UI 退役计划

- 状态：实施中 / 本地 dev 阶段检查点
- 编写日期：2026-09-28
- 适用范围：移除 Classic 和旧 Dragon，保留 Dragon Next 为唯一维护的 WebUI
- 当前进度：P0–P3 首轮已集成到本地 `dev`；P2 分页和 P4 路径契约已补强，Next 已补字段级撤销与完整帮助，P4 旧资产删除尚未开始，P5 未开始；未推送或发布

## 目标与边界

完成后，仓库只维护 `web/frontend-next/` 一套前端源码；继续使用现有 aiohttp API、训练服务及用户数据。
旧界面源码通过 Git 历史保留，不在活跃源码树内复制一套归档。`/next` 路径暂时保持，路径改名另行安排。

本计划涵盖依赖迁移、功能对账、入口收拢、旧资产及测试清理、部署说明和退役验收。
不包含界面重新设计、训练内核重构、新增模型能力，也不迁移或清理模型、配置、数据集、缓存、队列、历史和输出。

自动化写入验证使用临时数据、mock 或假训练进程；生产检查以只读为主。
真实 GPU 训练、外部计费调用、模型下载和真实标注写回如确需验证，另列资源范围并取得相应授权。
报告分别记录源码覆盖、自动化通过和真实使用结果，不用历史通过数字替代本轮验收。

## 删除与保留原则

| 对象 | 处理原则 |
| --- | --- |
| Classic / Dragon 页面、DOM 运行时和样式 | P4 按已核对清单删除，不按整个 `web/static/` 一刀切 |
| Next 借用的纯业务模块 | P1 迁入新版模块边界；迁移阶段保持行为，不同时重写规则 |
| 旧测试 | 删除纯旧布局/DOM 断言；字段、序列化、能力和操作契约迁到新归属继续验证 |
| 后端 API、服务和用户文件 | 保留；不以“旧前端调用过”为由删除后端能力 |
| favicon 等共用资产 | 按引用保留或迁移，验证构建及运行两类引用 |
| Next 前一入口和哈希资源 | 按发布与回退窗口保留；P5 验证上一候选版本可独立运行，不能只保留 HTML 而缺少其资源 |
| 历史文档和源码记录 | 源码由 Git 历史保留；历史文档按仓库归档规则保留证据并修复索引，不伪造历史完成状态 |

## 最终完成标准

- [ ] Next 构建和运行均不再依赖 Classic / Dragon 源码、DOM、样式或状态。

- [ ] 旧入口完成兼容映射，界面和错误恢复中不再要求切回旧 UI。
- [ ] 旧 UI 专属代码与配套已清理，保留的业务测试有明确归属。
- [ ] 类型检查、定向后端测试、前端测试、E2E、候选构建和回退检查有本轮结果。
- [ ] 文档、启动说明与维护协议以 Next 为唯一前端；用户数据和现有后台任务未被退役操作改变。
