# 历史任务日志

入口：`/next/history/<task-id>?view=logs`，或历史任务详情中的「日志」。

- 日志区域使用页面剩余高度，长行水平滚动；左侧行号固定。
- 连续滚动按需读取完整日志，不再限制最近 500 行。每页 400 条记录，可以按页或行跳转，或直接定位开头/末尾。
- 搜索框输入关键词并回车后，在服务端搜索整个日志文件；上下箭头循环定位前后匹配并显示匹配序号。搜索为不区分大小写的字面文本搜索，不是正则表达式。
- 搜索关键词会去除首尾空白；空关键词拒绝，最长 512 个字符。
- 「跟随末尾」用于查看新增记录；手动滚动或跳转后停止跟随。运行中任务每 3 秒检查新增日志；刷新按钮可主动重读。
- 下载按钮下载完整日志，而不是仅下载可见部分。页面不提供删除日志操作，不修改训练数据。

## 性能和兼容边界

前端最多缓存 12 页，仅渲染可视区域及少量预留行。虚拟滚动使用 10000 行的可移动坐标窗口，避免超长文件超过浏览器滚动高度限制；这不是日志条数上限。

后端每 256 条非空 JSONL 记录保存一个文件偏移，缓存最多 8 个文件版本；首次访问建立索引，后续分页直接 seek。全局搜索首次扫描完整文件，最多缓存 4 组关键词的紧凑匹配索引；前后匹配使用二分查找。文件大小、修改时间、inode 等变化会使旧索引失效。文件读取和搜索在工作线程执行，不占用 aiohttp 事件循环。首次超大文件索引或首次关键词搜索仍需要磁盘扫描时间。

行号沿用后端非空 JSONL 记录序号；损坏 JSON 或合法但非对象的 JSON 值显示解析占位，内嵌换行以 `↵` 显示，不挤占下一行。分页 API 新增 `indices` 字段以准确关联原始行号，其余分页与搜索接口不变。服务端校验任务 ID，并确保日志文件解析后仍位于该任务目录中。
