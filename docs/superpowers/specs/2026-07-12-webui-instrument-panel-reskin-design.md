## 1. 背景与目标

当前 WebUI 功能完整，但视觉语言不统一：

- 全局 token 与各页 forge 皮肤各自为政
- 页头 eyebrow、卡片、按钮、状态样式重复且层级不稳
- 有用户反馈字段名、配置项、数值偏小，默认缩放下阅读费力
- 同时又要求在 16:9 桌面默认缩放下尽可能多展示配置项

本次目标不是加功能，而是做一次**大幅换皮 + 视觉节奏统一**，让界面更像专业训练器的“精密仪器台”。

### 1.1 已确认决策

| 项 | 决策 |
|---|---|
| 力度 | 大幅换皮 |
| 气质 | 精密仪器台 |
| 改动边界 | 换皮 + 视觉节奏；不减配置项、不加功能 |
| 覆盖范围 | 7 个主 Tab 全做 |
| 主题优先级 | 浅色优先，深色单独精修 |
| 方案 | 方案 B：双主题精密仪表 |

7 个主 Tab：

1. 配置
2. 数据集
3. 训练
4. ΔW 分析
5. 全局设置
6. 环境检测
7. 生图测试

### 1.2 非目标

- 不新增功能入口
- 不删除、隐藏、合并任何配置项
- 不改训练/队列/历史/设置业务逻辑
- 不做信息架构重构
- 不做大模块搬迁
- 不把 `alert/confirm` 全面替换做成交互重构
- 不引入营销风 hero、大光球、厚重渐变装饰

## 2. 设计原则

### 2.1 气质

- 冷静
- 高对比
- 信息密但不乱
- 像训练器 / 示波器工作台
- 少装饰，多状态

### 2.2 核心原则

1. **层级靠表面，不靠大色块**  
   页面底 / 面板 / 输入区 / 悬浮层，最多 4 层。
2. **主操作唯一高亮**  
   每屏最多 1 个主 CTA。
3. **状态比装饰重要**  
   idle / running / error / warning / dirty / locked 必须一眼可辨。
4. **英文 eyebrow 降噪**  
   保留品牌微标签，但缩小、降对比，不再抢中文主标题。
5. **深浅双主题各自成立**  
   浅色：干净纸感 + 精密边线  
   深色：低发光仪器面板，不是浅色反相。
6. **字变大，壳变薄，装饰让路，内容留屏**  
   提升字段/控件可读性的同时，尽量保持 16:9 下一屏配置项数量。

## 3. 全局视觉系统

### 3.1 Token 层级

| 层级 | 浅色优先方向 | 深色对应方向 |
|---|---|---|
| 页面底 | 冷灰白，略带蓝 | 深灰蓝 / 近黑 |
| 面板 | 纯白或近白 | 抬起一层的板面 |
| 输入区 | 浅灰底 + 清晰边 | 更深输入槽 |
| 主强调 | 冷静蓝（操作） | 同色相，略提亮 |
| 成功 / 运行 | 稳绿 | 稳绿，避免霓虹 |
| 警告 | 琥珀 | 琥珀 |
| 危险 | 正红，克制 | 正红，克制 |
| 边框 | 可见但不脏 | 细而清楚 |
| 圆角 | 小圆角（约 6–8px） | 同 |
| 阴影 | 浅、短、功能向 | 更深、更收 |

实现上优先收敛到 `web/static/css/00-tokens.css`，各页 forge 皮肤改为消费全局 token，而不是继续散落硬编码色值。

### 3.2 字体与可读性

默认缩放下：

- 上调：字段名、输入值、关键数字、主按钮文案
- 下调：eyebrow、重复说明、次级 meta、装饰标签
- 不使用整页 `zoom` 作为主方案
- 系统级放大继续交给现有 UI 缩放设置

目标观感：

- 字段名不再像“小号注释”
- 输入框更高、更好点、更好认
- 关键指标数字层级清楚

### 3.3 组件规范

#### 按钮

统一四级：

- `primary`：主操作
- `secondary`：常用次操作
- `quiet`：低优先级操作
- `danger`：破坏性操作

规则：

- 同组按钮视觉重量分明
- hover / active / disabled 态统一
- 不再允许各页自定义“另一种主按钮味道”

#### Tab

- 未选中：弱文本 + 透明底
- hover：浅抬起 / 细边
- 选中：文本加强 + 轻微抬起 + 底部 2–3px 强调线
- 选中态与键盘 focus 态分离
- focus 使用清晰外环

#### 面板 / 卡片

- 统一内边距节奏：密而不挤
- 卡片头变薄
- 分组标题清楚，但不占大块竖向空间

#### 表单行

稳定栅格：

```text
标签 | 控件 | 帮助
```

规则：

- 标签与控件对齐稳定
- 帮助信息默认收敛，不默认撑满长文
- 只读态、错误态、脏数据态样式统一

#### 状态

统一状态胶囊 / 状态条：

- idle
- running
- compiling
- success
- warning
- error

规则：

- 同位置、同高度、同语义色
- running 可轻微呼吸，但必须尊重 `prefers-reduced-motion`

## 4. 壳层与导航

### 4.1 顶栏结构

```text
[ Logo / 产品名 ]  [ 7 个主 Tab ]  ........  [ 状态灯+文案 ] [ 教程 ] [ 主题 ]
```

规则：

1. 左侧品牌名短、稳，字重中等
2. 中左 7 个主 Tab 成为一组分段控制器
3. 右侧系统级控件视觉降一级
4. 顶栏 sticky，高度收紧，减少占屏

### 4.2 状态指示

保留现有状态语义，强化为状态胶囊：

- 圆点 + 短文案
- 运行中有克制动效
- 错误更醒目但不刺眼
- 位置固定在右侧，不随页面内容跳动

### 4.3 页面框架模板

每个主 Tab 统一为：

```text
薄页头（标题 + 一句说明 + 主操作）
内容区（左主工作台 / 右侧栏 或 单列）
状态反馈（页内 status）
```

说明：

- 不重做 IA
- 只统一标题、操作锚点、说明降噪方式
- 英文 eyebrow 收成页眉微标签

### 4.4 响应式

- 宽屏：单行顶栏
- 中屏：右侧控件更紧凑
- 小屏：Tab 可换行或均分宽度
- 本次不做汉堡菜单式导航重构

## 5. 七个 Tab 的页面节奏

总策略：

> 字变大，壳变薄，装饰让路，内容留屏。

面向常见 16:9 桌面宽度（约 1366–1920 宽）。

### 5.1 配置

目标：一屏看到更多字段，且每个字段更好读。

- 左侧主表单是绝对主角
- 右侧预设管理保留，但视觉降一级
- 训练来源三模式做成紧凑分段控件
- sticky 分类条保留为细导航，不占大标题区
- 字段名字号上调，输入框加高
- 长帮助默认折叠 / 弱化

### 5.2 数据集

目标：预设列表好扫，编辑区好填。

- 左：预设列表更像索引板
- 右：数据集行编辑更像参数表
- 顶部按钮视觉分组：
  - `新建 / 复制 / 重命名`
  - `导入 / 导出`
  - `保存` 单独强调
- 路径、重复次数、分桶参数等关键数字更醒目
- 高级 / 实验区二次降级，不抢主路径

### 5.3 训练

目标：监控一眼可读，队列 / 历史切换不晕。

- 顶部分段：`当前监控 / 队列 / 历史` 更像仪器切换开关
- 监控视图：关键指标卡更大字、更短标签
- 图表区给足宽度，次要控制收进轻量工具条
- 侧栏队列 / 最近任务更密，服务扫读
- Loss / 学习率 / 步数 / ETA / VRAM 数字层级提高

### 5.4 ΔW 分析

目标：先看结论摘要，再看排行和热力图。

- 顶部导入区压矮
- “默认解读”改成克制提示条，避免长文占屏
- 结果区主次：`摘要 -> 排行 -> 候选层 -> 热力图`
- 数字、占比、层名更清楚
- 对比模式用清晰 A/B 标识，不靠花色

### 5.5 全局设置

目标：路径和缩放设置好认、好改、不怕点错。

- 保留卡片分组：输出 / 模型 / 配置根 / UI 缩放
- 每卡标题更短，说明更薄
- 保存 / 重置位置稳定
- 路径输入框加高、字号加大
- 帮助不挤进输入行

### 5.6 环境检测

目标：像体检报告，不是日志墙。

- 主区：分组检查结果
- 侧 / 顶：错误、警告、总项数摘要
- 红项优先
- 检查项标题更大
- detail / hint 次级显示
- 成功项收敛，失败 / 警告跳出来

### 5.7 生图测试

目标：参数好调，结果区尽量大。

- 左侧参数板分区清楚：提示词 / 采样 / 权重 / 运行信息
- 右侧图库做主视觉区
- 日志与命令保留，但默认视觉降级
- 提示词框更高
- 数字参数对齐成稳定两列
- “开始生图测试”独占主强调

## 6. 可读性与 16:9 信息效率策略

为同时满足“字更大”和“多露配置项”，采用：

1. **上调内容字号，下调装饰字号**
2. **提高行效率，不靠缩小字**  
   减少无效空白、重复标题、过厚卡片头
3. **帮助信息让路**  
   帮助仍在，但不默认占满长文
4. **分组更清楚，间距更聪明**  
   组间分开，组内更紧
5. **主操作粘滞 / 固定锚点**  
   避免工具条反复打断表单阅读

明确约束：

- 不删配置项
- 不把高级项偷偷藏到找不到
- 不靠无脑整页放大
- 不牺牲 16:9 桌面主场景去讨好极端大字模式

### 7.1 主要改动面

1. 全局基础
   - `00-tokens.css`
   - `01-base.css`
   - `02-buttons.css`

4. JS

### 7.2 建议实施顺序

1. 全局 token / 壳层
2. 表单与按钮可读性
3. 7 页皮肤统一
4. 浅色精修
5. 深色对齐
6. 回归验收

### 7.3 风险控制

| 风险 | 控制 |
|---|---|
| 字变大后一屏变少 | 压缩页头 / 卡片头 / 重复说明，不压缩字段本身 |
| 各页 forge CSS 各自为政 | 先统一 token，再逐页替换重复色值 |
| 深浅主题漂移 | 同一组件规范，两套 token 映射 |
| 误伤 DOM / 测试 | 不改关键 id；少改 HTML 结构 |
| 范围膨胀到交互重构 | 严格限制为视觉与节奏 |

## 8. 验收标准

### 8.1 视觉一致性

- 7 个 Tab 能看出是同一套“精密仪器台”
- 按钮分级一致
- 页头、侧栏、卡片、表单行节奏统一
- 英文 eyebrow 不再抢主标题

### 8.2 可读性

- 默认缩放下，字段名、输入值、关键数字明显更好认
- 配置项相关文本不再有发虚小字观感
- 浅色模式长时间看表单不费力
- 深色模式对比度达标，不靠发光硬撑

### 8.3 16:9 信息效率

- 配置页在常见 16:9 桌面宽度下，一屏可见配置项数量不明显下降
- 通过壳变薄、装饰让路、帮助收敛换取字号提升
- 主操作始终可见

### 8.4 主题质量

- 浅色是主展示主题，干净、清楚、稳定
- 深色不是浅色反相，而是独立仪器面板质感
- 主题切换后，7 页没有半新半旧皮肤

### 8.5 回归安全

- 不破坏现有 DOM id 契约
- 关键前端静态测试可通过
- 不改变配置项集合与默认功能入口

### 8.6 验收方式

1. 视觉走查：7 Tab × 浅 / 深
2. 16:9 抽样：至少覆盖一个常见宽度配置页
3. 可读性对比：字段名、输入框、状态文字改前改后对照
4. 自动化回归：前端 DOM / 模块相关测试

建议至少覆盖：

- `tests/test_training_frontend_dom.py`
- `tests/test_training_frontend_modules.py`
- 其他与本次改到的前端契约直接相关的测试

## 10. 审核与多轮迭代机制

本次不只“做完换皮”，还要强制走：

1. **补充审核**
2. **交叉审核**
3. **多轮迭代**

参考协议：`docs/superpowers/specs/2026-07-11-five-round-auto-iteration-protocol.md`  
但本设计按“视觉换皮”裁剪，不照搬后端配置优化轮次。

### 10.1 审核分层

| 层级 | 名称 | 目的 | 时机 |
|---|---|---|---|
| L0 | 实施前自检 | 改动是否仍落在视觉边界内 | 每任务开始前 |
| L1 | 补充审核 | 找遗漏：对比度、密度、状态、主题漂移 | 每轮实现后 |
| L2 | 交叉审核 | 用不同角色互审，避免单人盲区 | 每轮收口前 |
| L3 | 回归门禁 | DOM/模块/缓存 token 测试 | 每轮必须 |
| L4 | 用户验收 | 可读性与 16:9 观感确认 | 关键里程碑 |

### 10.2 补充审核清单

每轮实现后，必须补审以下项，不能只看“好不好看”：

#### A. 边界审核
- 有没有偷偷加功能？
- 有没有减少 / 隐藏配置项？
- 有没有改 DOM id 契约？
- 有没有把帮助入口做丢？

#### B. 可读性审核
- 字段名是否明显更好认
- 输入值 / 数字是否更清楚
- 是否出现“字大了但更挤、更乱”
- 浅色长读是否仍费力

#### C. 16:9 密度审核
- 配置页一屏可见项是否明显变少
- 页头 / eyebrow / 卡片头是否已让路
- 主操作是否仍稳定可见
- 是否靠整页 zoom 偷懒

#### D. 主题审核
- 浅色是否干净、稳定、主展示可用
- 深色是否独立成立，而不是反相
- 7 页切换后有没有半新半旧

#### E. 状态与反馈审核
- idle / running / error / warning 是否清楚
- focus 是否可见
- reduced-motion 是否被尊重
- 危险按钮是否仍可识别

### 10.3 交叉审核角色

每轮至少启用 3 个只读审核角色并行，再由父代理汇总：

| 角色 | 审核焦点 | 输出 |
|---|---|---|
| `visual-auditor` | 气质、层级、按钮/卡片/Tab 一致性 | 视觉问题清单 |
| `readability-auditor` | 字号、对比度、表单行、16:9 密度 | 可读性 / 密度问题清单 |
| `theme-auditor` | 浅色优先质量、深色对齐、主题切换残留 | 主题问题清单 |
| `contract-auditor` | DOM id、CSS import token、测试契约、非目标越界 | 回归风险清单 |

规则：

- 审核角色默认 **只读**
- 可并行
- `max_depth=1`，审核角色不得再开孙代理
- 父代理负责冲突裁决与优先级排序
- 审核意见必须落到：
  - 问题
  - 位置
  - 严重度
  - 建议修复
  - 是否阻塞进入下一轮

### 10.4 多轮迭代节奏

采用 **5 轮视觉迭代**，每轮都走完整闭环：

```text
实现有限写集
  -> 补充审核
  -> 交叉审核
  -> 测试门禁
  -> 复盘记分
  -> 决定继续 / 返工 / 熔断
```

#### 轮次目标

| 轮次 | 目标 | 主要写集 | 出口标准 |
|---|---|---|---|
| R1 | 全局 token + 壳层定调 | `00-tokens` / `01-base` / `02-buttons` / header | 顶栏与基础组件统一，浅色主调成立 |
| R2 | 表单可读性与配置密度 | 配置页 + 共享表单样式 | 字段更好认，16:9 密度不明显下降 |
| R3 | 主流程三页对齐 | 配置 / 数据集 / 训练 | 三页同一仪器台语言 |
| R4 | 工具四页对齐 | ΔW / 设置 / 环境 / 生图 | 七页无半新半旧 |
| R5 | 深色精修 + 总收口 | 双主题扫尾 + 回归 | 浅深双过，门禁全绿 |

#### 每轮强制产出

1. 本轮改动摘要
2. 补充审核结果
3. 交叉审核结果
4. 测试命令与结果
5. 未关闭 High 列表
6. 下轮是否继续 / 返工 / 熔断

### 10.5 问题分级与处理

| 级别 | 定义 | 处理 |
|---|---|---|
| High | 破坏契约、配置项变少、严重难读、主题大面积漂移 | 本轮必须修，否则不能进下一轮 |
| Medium | 局部不一致、次级对比不足、密度小幅回退 | 优先本轮修；来不及则进下轮，但必须登记 |
| Low | 微调项、文案润色、极次要间距 | 可留到 R5 收口 |

### 10.6 测试门禁

视觉项目也必须有自动化回归，不能只靠肉眼。

#### 每轮最少门禁

```bash
timeout 60 .venv/bin/python -m pytest   tests/test_training_frontend_modules.py::test_frontend_module_graph_follows_production_entrypoint   tests/test_training_frontend_modules.py::test_frontend_module_cache_tokens_match_entrypoint   tests/test_training_frontend_modules.py::test_frontend_css_import_cache_tokens_match_entrypoint   tests/test_training_frontend_dom.py   -q
```

#### 关键轮加强门禁

- 涉及配置页：补 `tests/test_training_frontend_config_ui.py` 相关项
- 涉及训练/队列/历史壳层：补 live / queue / history 前端测试
- 涉及 ΔW / 生图：补对应 frontend modules 断言与服务契约测试
- R5 收口：跑 `tests/test_training_frontend_*.py` 相关集合

#### 视觉验收门禁

每轮至少做：

1. 浅色 16:9 配置页截图式走查或等价人工核对
2. 深色同页核对
3. 当前轮覆盖到的 Tab 切换核对

### 10.7 熔断条件

出现以下任一情况，立即停止扩写，先复盘：

1. 连续 2 轮 High 未清零
2. 本轮门禁失败率过高，或同一契约连续破两次
3. 审核发现配置项丢失 / DOM id 被改 / 功能被顺手重做
4. 16:9 配置密度明显变差，且没有可接受补偿方案
5. 深色或浅色出现大面积“半新半旧”

熔断后动作：

1. 冻结新写集
2. 只修 High
3. 重新交叉审核
4. 门禁转绿后才恢复迭代
